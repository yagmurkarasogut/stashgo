## Root cause
The production OTA bundle is baking the **preview** backend URL (from committed `frontend/.env`) instead of `https://media-vault-api.emergent.host`. On the EAS template the platform's redeploy is supposed to sed-swap the preview URL → deployed backend URL in `frontend/.env` before Metro bundles; for this app that prod value did not end up in the shipped bundle (phones hit preview → fail).

## IMPORTANT correction to the proposed remediation
`EXPO_PUBLIC_BACKEND_URL` is **NOT** a backend secret. On this platform the JS bundle's env comes from `frontend/.env` copied into Cloud Build at OTA-bundle time; the deployment **secrets store feeds ONLY the backend pod**, never the Metro bundle. So setting `EXPO_PUBLIC_BACKEND_URL` in the Deployments → Secrets panel will have NO effect on the published app. The correct lever is `frontend/.env` (+ the preview→prod swap) / `app.config.js`.

## Fix (for E1 to apply in the source env, then re-trigger deploy)
Make the prod backend URL deterministic in the bundle instead of relying on a string-match swap:
1. Source the backend URL through `app.config.js` `extra` and read it via `expo-constants`, OR guarantee `EXPO_PUBLIC_BACKEND_URL` resolves to the prod host at bundle time for production builds. Do not depend solely on the preview-URL sed match.
2. Keep your client hardening (explicit error when BASE is empty), and additionally treat a BASE that still contains `preview.emergentagent.com` as a misconfiguration so this surfaces loudly.
3. Re-publish: redeploy (new OTA) AND regenerate the APK/AAB (native build carries the bundle current at build time — the live APK is stale/preview-pointed).
4. Verify after redeploy: hit the prod backend from a real device and confirm requests appear in the prod backend logs (they currently do not). As a server-side sanity check, `POST https://media-vault-api.emergent.host/api/auth/register` with a fresh unique email returns 200 (confirmed equivalent already via probe registrations landing in prod Mongo).

## What I did NOT do
- No source mutation, no secret change, no redeploy — this is a source/config + verification handoff. Setting a secret would not fix it (see correction above).
